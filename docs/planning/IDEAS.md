# Idea Bank - Full Brainstorm Catalog

> **The exhaustive proposal catalog for `agents-platform`.** Every distinct idea from the brainstorm, deduped across ten personas, organized under the canonical roadmap themes. This is the long tail: if a feature was proposed by anyone, it lives here. For the curated, sequenced narrative see `ROADMAP.md`; for the consensus winners see the flagship docs. **This doc is the comprehensive index - nothing is dropped.**

## North Star

> Make `agents-platform` a deeply configurable, self-hosted multi-agent **control plane** where every agent run is visibly alive, fully instrumented, and governed by knobs an operator can turn from the UI - so that watching it work is the proof that real AI agents are doing real engineering work on real infrastructure.

Two design values dominate every idea below:

1. **Flexibility & configurability** - turn the 17+ scattered env vars, the 3-value model allowlist, and the ghost columns (`allow_writes`, `cost_budgets`) into live, UI-editable settings. Make agents, schedules, and compositions first-class versioned artifacts.
2. **Visibly showing off AI agents** - replace the 15-minute spinner with live streaming, parse tool-call steps, attribute real cost to every SSH run, and render multi-agent orchestration as something you can *watch*.

Every idea is scoped to be **realistically buildable by one engineer on a homelab K3s cluster** - leaning into the SSH dispatch seam as a feature, not apologizing for it.

## How to Read This Catalog

- **Themes (T1–T9)** are the canonical skeleton; each gets its own section with an idea table.
- **Effort**: `S` (a weekend), `M` (~1 week), `L` (multi-week), `XL` (major undertaking).
- **Impact**: `flagship` / `high` / `med` - alignment with the consensus flagship picks and north-star pull.
- **Proposed by** traces each idea to the persona(s) who raised it, so you can see consensus depth.
- Ideas explicitly parked appear in **Deferred / Not Now** at the end with rationale.

## T1 - Live Agent Theater

> Turn fire-and-forget runs into watchable, real-time experiences. **The single highest-impact demo transformation** - proposed as flagship by Pixel, Oracle, Tempo, and Sentinel independently. Today the platform's most powerful capability (multiple agents executing in parallel) is hidden behind a 15-minute spinner. `executor.js` buffers `child.stdout` into a string and only writes to SQLite after the SSH process exits. There is no WebSocket, no SSE, no partial transcript flushing anywhere in the stack.

## T2 - Full-Spectrum Observability

> Close the SSH telemetry blind spot. Today `recordTrace()` is **never called from `executor.js`** - every scheduled SSH run produces zero trace rows, so the cost dashboard is empty despite real runs completing. The `claude -p --output-format json` response already contains a `usage` object (`input_tokens`, `output_tokens`) that `parseClaudeJson()` currently discards. This is the **#1 "embarrassing gap"** in the brief - flagged by 8 of 10 personas.

## T3 - Agent Governance & Safety

> Wire the inert `allow_writes` column into a real tiered safety policy engine. Today `safety-prompt.js` exports **one hardcoded `SAFETY_PREAMBLE` string** applied universally; `allow_writes` is stored, validated by Zod, displayed in the UI, and documented - but **never read** by `executor.js` or `workflows/runner.js`. A staff engineer reviewing the code immediately flags it as unfinished work. There is no auth anywhere, and the platform runs `--dangerously-skip-permissions` on a real K3s cluster.

A single feature that transforms the platform from a cron scheduler into an event-driven agentic runtime - a Prometheus alert fires Atlas + Sentinel, a git push fires Tempo + Flux via `POST /api/webhooks/:token` → existing `scheduler.fireRun()`. The prerequisite that unlocks the n8n bridge, Prometheus integration, and the catalog. Medium effort, no new external deps.
- **Hot take:** The **Discord notification at `scheduler.js` lines 95–114 is doing more to showcase this platform as a real system than all twelve React pages combined** - yet it's a single hardcoded env var with no routing, no per-schedule control, no delivery log. Before adding any new AI feature, ripping out `DISCORD_WEBHOOK_URL` and replacing it with a DB-driven router with a test-ping button would do more for the portfolio impression than another LangGraph graph. "Observability of your own notification pipeline is a signal of engineering maturity."

### Sentinel - Reliability & Run Observability
- **Flagship:** **Live Run Streaming via SSE + Step-Level Progress** (T1.1 + T1.3). The single highest-leverage visual change - 5 agents reasoning in parallel is currently invisible during execution. No new deps, M effort, transforms a batch scheduler into a live orchestration system. Combined with tool-call visualization (parsing `tool_use` blocks), the platform shows not just *that* agents run but *what they're doing* step by step. "The 'show your work' moment that proves the platform is genuinely agentic."
- **Hot take:** **The eval framework is applied to the wrong thing.** Today it evaluates synthetic test cases against prompts in isolation - useful for regression testing but invisible during normal operation. The real opportunity is to **turn every scheduled run into an eval event**: score it with the Haiku judge, trend the scores, and let the platform tell you when Sentinel's quality dropped after you edited its prompt last Tuesday. **Evals-as-observability, not evals-as-QA.** Almost no hobbyist portfolio does continuous quality measurement on agent outputs.

### Flux - Config, Templates & GitOps Lead
- **Flagship:** **Safety Policy Engine** (T3.1 + T3.2). Directly fixes the longest-standing gap (`allow_writes` inert since day one), turns a ghost column into a real governance primitive, and produces the most interview-impressive demo: a hiring manager sees exactly why Atlas's GitOps sync has different permissions than Sentinel's read-only audit - enforced by a **versioned YAML artifact**. Combined with SSH telemetry backfill (effort S), both ship as a coherent "AI agent governance" story.
- **Hot take:** **`agency-sync.js` is the platform's most underused architectural idea.** It already pulls YAML-frontmatter agents from GitHub, parses, and upserts into SQLite - then dead-ends into a read-only catalog that can't be scheduled, composed, or evaluated. Add an "Adopt" button that copies an agency agent into the runnable table with a `source_pack` tag and you have a community agent marketplace with **zero additional infrastructure.** "The Agent Pack feature is not new - it's finishing what `agency-sync.js` already half-built."

## Deferred / Not Now (with rationale)

Captured here so the long tail is complete - these were considered and explicitly parked.

| Idea | Theme | Why parked |
|------|-------|-----------|
| **Postgres / TimescaleDB migration** (Ledger, XL) | data model | Premature; SQLite + a retention policy handles homelab scale. The DB-adapter abstraction is nice but the migration risk outweighs benefit until a real multi-replica need emerges - and it must coordinate with the separately-specced cross-app centralized Postgres effort. |
| **K3s Job-per-run dispatch** (Tempo, L; new RBAC + runner image) | runtime | The SSH dispatch model is a feature to **lean into, not replace** (Forge's hot take). Not worth the complexity for a single-host portfolio demo. |
| **Multi-workspace / multi-tenant schema** (Ledger, L; touches 6 tables) | data model | A single-user homelab doesn't need namespace isolation yet; adds migration risk for speculative benefit. |
| **Mid-run WebSocket veto** (Vault, L) | T1/T3 | SSE streaming + the approval gate (T3.3) cover the supervised-autonomy story without the extra `ws` dependency and connection management. (The lighter SSE-based interrupt, T1.5, may still be worth it.) |
| **Published npm SDK + full OpenAPI generation** (Forge) | T7 | API-key auth + documented REST is enough; a polished SDK is over-investment for a portfolio piece. |
| **n8n custom community node package** (Relay) | T7 | Outbound + inbound webhooks already bridge n8n bidirectionally; a packaged node is diminishing returns. |
| **Run anomaly detection on every run** (Sentinel) | T2 | Compelling but adds per-run cost/latency; fold into the eval-as-observability story only after the eval judge is configurable (T6.3). |
| **Meeting transcript structured parser** (Ledger) | T5 | Nice-to-have polish; the streaming Theater view already makes meetings watchable. (Synthesis endpoint, T5.5, retains standalone value.) |
| **Pluggable HTTP/script tool registry** (Forge) | T8 | Powerful but expands the attack surface significantly; gate behind the safety policy engine and revisit after governance is solid. |
